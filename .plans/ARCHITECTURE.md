## System Overview

Two layers: a **host CLI** manages the lifecycle, a **container daemon** runs the bot.

```
Host machine                         Docker container (node:22-slim)
┌──────────────┐                     ┌─────────────────────────────────────┐
│  alf CLI     │  docker compose     │  alf-daemon (PID 1, user: node)    │
│  cmd/alf/    │ ──────────────────► │  cmd/alf-daemon/                   │
│              │                     │                                     │
│  Manages:    │                     │  ┌──────────┐  ┌─────────────────┐ │
│  - init      │                     │  │ Telegram  │  │ Control Center  │ │
│  - start     │                     │  │ poller    │  │ :8080           │ │
│  - stop      │                     │  └─────┬────┘  └────────┬────────┘ │
│  - upgrade   │                     │        │                │          │
│  - login     │                     │        ▼                │          │
│  - secrets   │                     │  ┌──────────┐           │          │
│              │                     │  │ Claude   │  reloadCh │          │
│              │                     │  │ subprocess│◄──────────┘          │
│              │                     │  │ (user:    │                      │
│              │                     │  │  claude)  │                      │
│              │                     │  └──────────┘                      │
└──────────────┘                     └─────────────────────────────────────┘
```

## Privilege Separation (Two-User Model)

| User | UID | Group | Runs | Home | Purpose |
|------|-----|-------|------|------|---------|
| `node` | 1000 | node, alf | daemon, CC, all background systems | `/home/node` | Full access to data, config, logs |
| `claude` | 1001 | claude, alf | Claude CLI subprocess only | `/home/node/data` | Writes to alf-managed dirs + `.claude/` |

Shared group `alf` (GID 1002) — both users are members. Enables claude to write to `data/config/`, `data/tools/`, `data/skills/` via group permissions (0775).

Claude is spawned via `SysProcAttr.Credential{Uid:1001, Gid:1001}` with `HOME=/home/node/data` — kernel-enforced, no shell wrapping.

## Packages

| Package | Role |
|---------|------|
| `cmd/alf/` | Host CLI router (init, start, stop, upgrade, login, secret, uninstall) |
| `cmd/alf-daemon/` | Container entry point — Telegram loop, command routing, Claude invocation |
| `internal/cli/` | All CLI command implementations + embedded templates |
| `internal/controlcenter/` | HTTP dashboard, auth, config/tiers/resource CRUD, stores, middleware |
| `internal/telegram/` | Markdown→HTML formatting, chunking, Telegram API client |
| `internal/session/` | Claude session persistence (--resume support) |
| `internal/eventlog/` | JSONL event logger (daily rotation) |
| `internal/gittrack/` | Git version history for data directory |
| `internal/updater/` | GHCR tag polling for new image versions |

## Data Flow

```
Telegram message
  → daemon: getUpdates() long-poll
  → eventlog: log message_in
  → command routing (/login, /new, /help) OR:
  → askClaude(prompt, model, resumeID)  ← runs as UID 1001
  → session store: persist session_id
  → telegram.SendMessage() → markdown→HTML → chunk → send
  → eventlog: log message_out
```

## Volumes & Permissions

### Host directory (`~/alf/`)

```
alf/
├── docker-compose.yml          generated by alf init
├── secrets/                    mode 0700
│   ├── telegram_bot_token      mode 0600
│   ├── telegram_chat_id        mode 0600
│   └── cc_auth_token           mode 0600
├── config.d/                   → /home/node/data/config.d (ro mount)
│   ├── config.json             CC-managed config
│   └── tiers.json              CC-managed tiers
├── data/                       → /home/node/data (rw)
│   ├── .claude/                alf's CLI auth + session cache (claude:claude, 0700)
│   ├── config.d/               ro mount from host config.d/
│   ├── config/                 alf-generated configs (claude:alf, 0775)
│   ├── tools/                  alf-generated tools (claude:alf, 0775)
│   ├── skills/                 alf-generated skills (claude:alf, 0775)
│   ├── logs/events/            JSONL per day
│   ├── sessions/               session_map.json
│   └── .git/                   gittrack repo (if enabled)
├── tools.d/                    → /home/node/data/tools.d (ro mount)
└── skills.d/                   → /home/node/data/skills.d (ro mount)
```

### Tools & Skills: dual-path model

Claude sees everything under `/home/node/data/`:

```
data/
├── config.d/   read-only   CC-managed config (ro mount from host)
├── config/     read-write  alf-generated configs (claude:alf, 0775)
├── tools.d/    read-only   system/user drop-ins (ro mount from host)
├── tools/      read-write  alf-generated tools (claude:alf, 0775)
├── skills.d/   read-only   system/user drop-ins (ro mount from host)
├── skills/     read-write  alf-generated skills (claude:alf, 0775)
└── ...
```

- **`.d` directories** — user curates on host, mounted read-only. Convention: never modified at runtime.
- **Plain directories** — alf-managed, writable by both daemon (via group) and Claude subprocess.

### Permission matrix

| Path | Owner | Mode | node (daemon) | claude (subprocess) |
|------|-------|------|---------------|---------------------|
| `data/` | node:node | 0755 | read/write | read-only |
| `data/config.d/` | node:node | 0755 | read/write (CC) | read-only |
| `data/tools.d/` | node:node | 0755 | read-only (ro mount) | read-only |
| `data/skills.d/` | node:node | 0755 | read-only (ro mount) | read-only |
| `data/config/` | claude:alf | 0775 | read/write (group) | read/write |
| `data/tools/` | claude:alf | 0775 | read/write (group) | read/write |
| `data/skills/` | claude:alf | 0775 | read/write (group) | read/write |
| `data/.claude/` | claude:claude | 0700 | **none** | read/write |
| `data/logs/` | node:node | 0755 | read/write | read-only |
| `data/sessions/` | node:node | 0755 | read/write | read-only |
| `data/.git/` | node:node | 0755 | read/write | read-only (git log) |

### Ownership fixup

`fixVolumePermissions()` (called during init + upgrade):
- `data/` → chown 1000:1000 (node)
- `config.d/` → chown 1000:1000 (node)
- `data/.claude/` → chown 1001:1001, chmod 700 (claude-private)
- `data/{config,tools,skills}/` → chown 1001:1002, chmod 775 (claude:alf)

## Control Center

HTTP server on `:8080`, embedded in daemon process.

### Auth

Two mechanisms (either works):
1. **Token**: `CC_AUTH_TOKEN` in header/cookie — for API/automation
2. **Magic link**: Telegram `/login` → inline keyboard (24h/7d/30d) → one-time code → session cookie

### Routes

| Route | Auth | Method | Purpose |
|-------|------|--------|---------|
| `/health` | no | GET | Health check |
| `/auth?code=` | no | GET | Magic link consumption |
| `/` | yes | GET | Dashboard (embedded HTML/JS) |
| `/api/config` | yes | GET/POST | Config CRUD |
| `/api/tiers` | yes | GET/POST | Tier definitions |
| `/api/status` | yes | GET | Daemon stats |
| `/api/logs/{name}` | yes | GET | Tail log files |
| `/api/{memories,tools,skills}/*` | yes | CRUD | Resource management |

### Hot reload

```
CC: POST /api/config → configStore.Save() → notifier.Notify(ReloadConfig) → reloadCh
daemon: select reloadCh → configStore.Load() → apply new config
```

Same pattern for tiers, tools, skills.

## Background Systems

| System | Trigger | Configurable | Purpose |
|--------|---------|--------------|---------|
| **Telegram poller** | 30s long-poll loop | no | Core message ingestion |
| **Event logger** | every message in/out | no | JSONL audit trail, daily rotation |
| **Session store** | every Claude response | `session_timeout` (min) | `--resume` for conversation continuity |
| **Git tracker** | config/tier changes + periodic sweep | `git_track`, `git_sweep_interval` (min) | Version history for data/ |
| **Update checker** | periodic poll to GHCR | `auto_update_check`, `auto_update_check_interval` (sec), `auto_update_notify` | Notify on new image versions |
| **Magic link cleanup** | background goroutine | no | Expire unused codes |
| **Session cookie cleanup** | background goroutine | no | Expire old CC sessions |

## Secrets

Docker Compose secrets mechanism. Daemon reads via `readSecret()` — checks `{VAR}_FILE` path first, falls back to env var.

| Secret | Required | Used by |
|--------|----------|---------|
| `TELEGRAM_BOT_TOKEN` | yes | Telegram API |
| `TELEGRAM_CHAT_ID` | yes | Default chat for notifications |
| `CC_AUTH_TOKEN` | no | Control Center auth |
| `ALLOWED_CHAT_IDS` | no | Login authorization (defaults to TELEGRAM_CHAT_ID) |

## Immutable vs Mutable

### Immutable (set at build/deploy time)
- Docker image (`ghcr.io/alamparelli/alf:latest`)
- Binary `/opt/alf/alf-daemon`
- Claude Code CLI (`npm install -g`)
- User accounts (node UID 1000, claude UID 1001, alf GID 1002)
- Container resource limits (512MB, 0.5 CPU)
- Port mapping

### Mutable by daemon (at runtime)
- `data/config.d/config.json` — via CC or hot reload
- `data/config.d/tiers.json` — via CC
- `data/logs/events/*.jsonl` — event logger
- `data/sessions/session_map.json` — session store
- `data/.git/` — gittrack commits

### Mutable by Claude subprocess (via alf group)
- `data/.claude/` — CLI auth + session cache (claude-private, 0700)
- `data/config/` — alf-generated configs (claude:alf, 0775)
- `data/tools/` — alf-generated tools (claude:alf, 0775)
- `data/skills/` — alf-generated skills (claude:alf, 0775)

### Mutable by host user only
- `secrets/*` — via `alf secret set`
- `docker-compose.yml` — via `alf init` or manual edit
- `config.d/`, `tools.d/`, `skills.d/` — system drop-ins, user curates on host
