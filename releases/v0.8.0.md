# Release v0.8.0

## What's New

### App iframe auth — no more dead-end 401s (#325)

Sandboxed app iframes used to toast "Session expired — reload page" on any 401, even when the parent still had a valid session cookie. A suspended tab or a throttled `setInterval` easily missed the 4-minute token refresh, and every subsequent API call was permanently broken until manual reload.

`AlfSDK.api()` and `AlfSDK.fetch()` now ask the parent for a fresh token on 401 (via the existing MessageChannel), retry the request exactly once, and only surface the "session expired" state if that retry also fails. Concurrent 401s share a single in-flight refresh, so N parallel calls don't hammer the parent for N tokens. No new endpoint, no new session surface — the iframe still can't mint its own tokens.

### Auth-fail logs now explain themselves (#325)

Previous format (`[CC] auth fail: has_auth=true auth_len=23 token_len=64`) gave byte lengths instead of a reason. Diagnosing an app-iframe 401 loop from logs alone was impossible.

New format emits a reason code and also fires on `/apps/*` paths (previously only `/api/*`):

```
[CC] auth fail: ip=127.0.0.1 method=GET path=/apps/todo/api/todo reason=app_token_invalid_or_expired
```

Reasons: `no_credential`, `bearer_header_rejected`, `bearer_cookie_rejected`, `session_cookie_rejected`, `cookies_rejected`, `app_token_invalid_or_expired`, `app_token_slug_mismatch`, `app_token_route_not_allowed`. No token or cookie values are ever logged.
